使用场景引导（快速上手）

按你的场景直接看对应小节；详细内容见各功能章节与 给 AI 的引导。

场景一：创建凭据让 WArmy 使用

  1. 「中继」页 → 「生成凭据」→ 填名称（限额可留空继承默认）→ 生成。
  2. 明文只显示一次，立即复制。
  3. 可选填端点：域名/IP（默认公网 IP）+ 端口（默认 59599）——写进凭据提示。
  4. WArmy 客户端「服务器设置」填服务器地址（IP:59599）+ 该 token 即可连接。

场景二：创建凭据让其他 FWArmy 使用（F中继）

  1. 「F中继」页 → 「生成接入凭据」→ 名称（地址默认公网 IP，端口默认 58588）。
  2. 端口不在监听集合会自动添加并监听（被占用则端口页处理）。
  3. 把 fwnexp_v2_... 凭据发给对方；对方在「扩网」页填「名称 + 凭证」即可连到本站。

场景三：如何添加扩网（本站连接其他 FWArmy）

  1. 「扩网」页 → 「添加」→ 名称 + 对方的被扩网凭据（自带地址端口）。
  2. 「识别指纹」→「信任」（TLS 指纹固定）。
  3. 转发按序尝试最多 3 个上游、8 秒预算、成功即停。

场景四：常见错误异常情况排查（错误码速查）

错误含义处理
401 unauthorized凭据无效/缺失重新生成凭据
401 credential-expired凭据过期管理页延长有效期
401 credential-port-unavailable凭据端口不可用端口页启用/强制启用
400 bad-msg-id缺 msgId客户端必带 msgId
400 legacy-token-not-supported旧版被扩网凭据用新版（自带地址）凭据
403 admin-local-only管理面仅本机回环服务器本机访问或 SSH 隧道
503 not-accepting服务器暂停接收管理页恢复「接受新投递」
429 限额超出限额提高限额或等待窗口
426明文被拒（需 TLS）配置 TLS/固定指纹

场景五：WArmy 无法连接本中继

  1. 凭据复制是否完整（无空格）；端口页 59599（或所选端口）是否监听。
  2. 云安全组/防火墙放行 TCP 端口；从外部 telnet 服务器 IP 端口 验证可达。
  3. TLS 指纹是否固定（重新生成证书后指纹变了需更新）。
  4. 服务器是否「接受新投递」（暂停中 503）。

场景六：其他 FWArmy 无法连接本中继

  1. 对方用的是 F中继页的 fwnexp_v2_ 凭据（不是中继 token）。
  2. 凭据自带地址端口公网可达；端口页状态正常。
  3. 对方「识别指纹 → 信任」完成。
  4. 看 data/server.log 被拒原因（401/426/403）。

场景七：无法扩网

  1. 对方凭据是否新版（fwnexp_v2_ 自带地址）；「识别指纹 → 信任」完成。
  2. 对端在线/端口可达（扩网页「测试连接」）。
  3. 本站 DHT 入网（DHT 页 contacts/锚点引导）。

场景八：其他常见错误排查

  • 检测更新报「读取更新状态失败」：多为页面/程序版本不匹配，升级最新版。
  • 托盘图标不显示：需交互桌面会话（RDP 登录）+ 不带 --no-tray；看任务栏「^」展开。
  • 双击 exe 弹控制台：旧版本（≤0.7.6）是控制台子系统，升级 0.7.10+。
  • DHT contacts 为 0：锚点 UDP 443/62666 需公网可达（云安全组 + 防火墙 UDP 放行）。

快速开始

FWArmy 是 WArmy 的专属中继服务器：WArmy 客户端把消息投递到 FWArmy，FWArmy 负责入队、按凭据与限额放行、跨站转发（扩网/F中继）、以及 DHT 设备发现。启动后浏览器打开管理页（默认 http://127.0.0.1:8787）。

  • 启动：双击 FWArmy.exe（单文件）或 node server.mjs --port=8787 --data=<数据目录>（源码）。
  • 停止：管理页右上角「正在运行」按钮，或命令行 node ctl.mjs stop（挂死加 --force）。
  • 数据目录：config.json（配置）、credentials.json（中继凭据 sha256）、expand.json（被扩网凭据）、addition-audit.log（附加内容审计链）、tls/（自签证书）、server.log（日志）。
  • 管理页安全：只接受本机回环访问（127.0.0.1 / ::1），拒绝跨站请求。远程管理请用 SSH 隧道（见 FAQ）。
管理入口端口（默认 8787）不可暂停/删除，只能在「端口」页更改；改后下次访问用新端口，旧端口继续作为普通业务端口监听。

中继（WArmy 客户端接入本站）

中继凭据 = WArmy 客户端连接本站的通行证。服务器只存凭据的 sha256 哈希，明文只在生成时显示一次。

生成凭据

  • 「中继」页点「生成凭据」，名称默认已填（可直接保存）。留空限额 = 继承全局默认；填 0 = 不限制。
  • 可选的「端点域名/IP + 端口」会写进凭据提示（默认 = 探测到的公网 IP；端口不填默认 59599）。
  • 分钟次数与流量必须大于 0；其余额度填 0 = 不限。

凭据管理

  • 每行凭据显示：名称 / 标识（中间 5 + 末尾 5）/ 限额 / 今日/本月/累计用量 / 峰值 / 最近使用。可编辑、停用、删除（删除需输入名称确认）。
  • 限额语义：次数 = 有效凭据的业务请求（含拒绝/失败）；流量 = 实际入队与取走的信封字节之和。重启清空分钟窗口，不清累计额度。
  • 凭据端口（填了端点时）：不在端口列表会自动添加并监听；被占用则端口页显示异常，可强制启用或改用其他端口。

附加内容（会话提示消息）

详见 附加内容 一节。

F中继（别人连接本站）

别的 FWArmy 投递失败时，用你生成的「被扩网凭据」把消息转给你，由你尝试投递。每个实例可生成多条，可单独管理/停用/删除。

  • 生成时填写的域名/IP（默认 = 探测到的公网 IP）和端口会写进凭据本身（不填端口默认 58588）；对方只需填「名称 + 凭证」，不用再填地址。
  • 凭据端口不在监听集合时自动添加并监听（R142 起）；若被占用（端口页红色「异常」）需在端口页强制启用或改用已监听端口。
  • F中继收到的消息不允许添加附加内容；且必须已带附加内容或密封标记，否则丢弃（防旧版本/被改造的上游站）。
  • 「F中继」页表格 = 别人交给我投递的统计（次数/字节/成功/失败/最近结果）。
「⚠ 端口 58588 不在本机监听端口集合」= 生成凭据时 58588 未在监听（被占用没起来 / 被暂停 / 被删除）。处理：端口页启用 58588，或改用已监听的端口生成；R142 起生成时也会自动添加该端口并尝试监听。

扩网（本站连接别人）

本站无法投递的消息（收件人离线/不在本站），按顺序转发给已配置的互信 FWArmy（凭据 + TLS 指纹固定）。

  • 添加扩网：只需填「名称 + 对方的被扩网凭据」（凭据自带地址和端口），凭据不兼容旧版（不含地址）。
  • 证书指纹：默认需要固定对方的 TLS 指纹——添加后点「识别指纹」→「信任」。
  • 转发规则：按序逐个尝试最多 3 个上游、整次 8 秒预算、成功即停；DHT 定位命中的站排最前；对端 409/426 不再换下一个。
  • 「扩网」页表格 = 我转发出去的统计（请求/流量/成功/失败/最近结果/最近测试）。
  • 转出消息必带附加内容或密封标记（接收站不会再添加）。

DHT 组网（设备发现层）

DHT 是设备发现网络：所有 FWArmy 通过它互相「找到」，但发现 ≠ 授权——消息投递永远走配置的凭据 + TLS 指纹固定。DHT 强制开启，不可关闭。

入网与锚点

  • 默认锚点（自动生效，不可删除）：DHT.pondsi.com / DHT2.pondsi.com / dht.numumu.com × UDP 443/62666。第一台设备不需要别人引导——启动即向公网锚点引导并发布本站记录。
  • 手动锚点：填 host 或 host:port 添加（如对方的公网 IP:UDP 端口）。对方可引导你的地址 = 对方对外地址行内的「引导地址」（host × UDP 端口，可一键复制）——把任一地址告诉对方，对方添加后即可引导到本机。第二台设备以第一台为锚点后自动入网、双向可发现。
  • 锚点全部不可达时指数退避重试（200ms→60s）；无锚点时本机仍监听 UDP 并自发布（以本机为锚点的设备可反向发现本站）。

引导地址（让别人引导本机）

本机对外地址每一行都显示「引导地址」= 同一 host × UDP 端口（443/62666），带复制按钮：把该地址告诉其他 FWArmy，对方在「手动锚点」添加即可引导到本机（引导 ≠ 投递：投递仍走对外地址的 TCP 业务端口并需互信凭据）。注意：锚点地址必须用 UDP 端口，不能把对外地址（TCP 业务端口）直接填进锚点。

对外地址（发现后连接地址）

  • 别人通过 DHT 发现本机后，用什么地址连接本机 = 本站记录里宣告的地址（host + 端口）。默认自动宣告：探测到的公网 IP × 业务 TCP 端口（59599/58588/8787 等），无需手动填写。
  • 手动添加 = 覆盖自动宣告：填域名或指定端口（如锚点服务器宣告 DHT.pondsi.com:59599 而非 IP）。必须指向本机（域名解析到本机或 IP 为本机），验证通过才宣告，每 5 分钟复查。
  • 自动兜底（全部手动失效/暂停时）：公网 IPv4/IPv6 × 业务 TCP 端口，不可改删，只能暂停；定时自检自动恢复。
  • 每行下方显示「引导地址」 = 同一 host × UDP 端口（443/62666）——别人引导本机入网用（引导 ≠ 投递）。
  • 投递仍需互信凭据（发现 ≠ 授权）：别人发现本站后，须持有本站的接入凭据（F中继页生成）才能投递。

地址解析与 IPv6

  • 域名解析优先 IPv6（AAAA 记录），IPv6 不可达时自动回退 IPv4（R135d 起）。
  • 配置域名时注意：配了 AAAA 就必须保证服务器有公网 IPv6 且防火墙放行 IPv6 UDP，否则引导走 IPv6 不通（现在会自动回退 IPv4，仅增加一次超时）。
  • 对外地址与兜底同样 IPv6 优先；无 IPv6 时用 IPv4。

对端表

路由表里最近的节点。客户端注册到本机时，本机会把「该客户端当前所在中继站 = 本站」签名发布到 DHT（每 10 分钟保鲜，离线约 30 分钟过期）；其它中继站投递失败时据此定位目标所在站。

端口管理

FWArmy 默认监听：8787（管理入口）· 59599（中继凭据默认）· 58588（扩网凭据默认）· DHT UDP 443/62666（组网引导）。被占用的端口不会自动顺延，而是标为「异常（被占用）」。

  • 添加端口：先选协议——TCP（业务：中继/扩网凭据用）或 UDP（DHT 组网监听）。
  • 暂停：停止监听但保留配置（UDP 端口也一样，随时可「启用」恢复，不会消失）。DHT 至少保留一个未暂停的 UDP 端口。
  • 强制启用：结束占用该端口的进程后开始监听——本机操作，慎用。
  • 删除：立即停听并移除，引用该端口的凭据自动失效。
  • 管理入口端口（标「入口」）：不可暂停/删除，只能改端口号。
  • 凭据端口不在列表时自动添加并监听（生成中继/F中继凭据时）；被占用则显示异常（可强制启用）。
  • 状态样式：监听中 = 绿框绿字；异常 = 红框红字；暂停 = 白字无框。

附加内容（会话提示消息）

中继站可以在转发的消息上附加一条纯文字提示（如公告/欢迎语）。WArmy 客户端每个会话 25 小时内最多展示一条（客户端去重）；附加内容开头有 ⓘ 图标位，纯文本单行显示。

内容库

「中继」页的附加内容面板：每行一条，最多 1000 条；纯文字校验（无 HTML 特殊字符、无换行、单条 ≤120 字节（约 30 个中文字 / 60 个英文字符，一行）），非法条目自动过滤。

凭证级模式

生成/编辑中继凭据时配置：关闭（默认，不加）/ 随机 / 按顺序循环 / 按频率比例。

权重表（可选）：序号:权重 逗号分隔（如 1:100,3:50，支持中文逗号/冒号/全角数字）。只写要使用的条目，未写出的不参与（想排除某条就不写它）；留空 = 全部参与等权。「按频率比例」模式权重大小 = 出现比例（100:50 ≈ 2:1）；「随机/按顺序循环」模式只用权重表圈定参与条目（权重大小不影响）。非法输入（如字母、感叹号、分号、缺冒号）会提示格式错误且不保存。

添加规则

  • 只有中继（客户端直投本站）或扩网转出（本站转给上游）时按该凭据配置添加；F中继（别人转给本站）一律不添加。
  • 客户端方向携带附加内容字段 = 异常，直接丢弃（400）。
  • 全链每条消息最多一条：本机转出时若未添加则补密封标记，接收站见附加内容或密封标记一律不再添加。

防篡改与审计

  • 每次添加都写入哈希链审计（addition-audit.log，只存哈希）；链根每 5 分钟签名发布到 DHT（防回滚检查点），改造站删除/替换附加内容会留下可对照证据。
  • WArmy 客户端：同一 msgId 多份副本对比附加内容与路由，不一致 = 篡改 → 不展示并标记可疑站；24h 内同一会话同一中继 ≥2 次附加 → 丢弃并临时禁用该中继（24h→48h→7d 退避）。

消息安全（唯一 ID · 重放闸 · 黑名单）

  • 每条消息必须有 msgId（客户端显式给出）；缺失/空串直接丢弃（400）。
  • 同一 msgId 在本实例 24 小时内最多放行 2 次；第 3 次或首次出现已超 24 小时 → 丢弃并写入黑名单（30 天未再出现自动清理，重启保留）。
  • msgId 被来源 Ed25519 签名覆盖：中间节点改写 → 验签失败（403），无法伪装新消息绕闸。
  • 防环：转发时每站把自己的实例 ID 追加进 route；route 含本站 → 409 拒绝（环形网第一轮即截断）。

TLS / 证书

  • 默认自签证书 + 指纹固定（开箱即用，无需购买证书）；也可配置用户证书（CA 校验）或显式关闭 TLS（危险，不推荐）。
  • 非回环来源的明文业务请求默认 426 拒绝。
  • 改动 TLS 配置需要重启生效。自签私钥加密落盘。

自动更新

  • 单文件（SEA）运行时可自动更新：从 GitHub Releases 下载 → 校验 SHA-256 → 替换 → 重启自检（产品/版本/数据目录身份），失败回滚。源码运行只检查不安装。
  • 策略：关闭 / 检查并提示（默认）/ 自动下载并重启。重启会清空内存队列（消息 TTL 30 秒）；队列非空时自动安装会被拒绝。

常见问题

「⚠ 端口 58588 不在本机监听端口集合」？

58588 是 F中继凭据默认端口。R142 起生成凭据时端口不在监听集合会自动添加并监听；若仍提示异常 = 端口被占用（强制启用或换端口）。处理：端口页查看状态（红色异常 = 被占），强制启用或改用已监听端口。

「端口不可用，请在端口中设置」？

该凭据的端口未被监听（被占/被暂停/被删除）。R142 起生成时自动添加并尝试监听；被占时点提示里的「端口」链接跳到端口页，强制启用或添加后重新生成凭据。

管理页一直弹「端口读取失败: Failed to fetch」？

旧版服务器 keep-alive 超时（5 秒）与管理页 5 秒轮询撞车导致连接被重置；R135f 起服务器超时已调到 30 秒且请求自动重试一次，此问题已修复。仍出现时检查网络/防火墙。

如何远程管理服务器上的 FWArmy？

管理页只接受本机回环访问（安全边界）。远程管理请用 SSH 隧道：ssh -N -L 8787:127.0.0.1:8787 用户@服务器，然后本地浏览器打开 http://127.0.0.1:8787。

DHT 域名配了 AAAA 但服务器没有 IPv6？

解析优先 IPv6；R135d 起 IPv6 不可达会自动回退 IPv4（增加一次超时）。长期建议：无 IPv6 时只配 A 记录。

第一台设备如何入网？

不需要别人引导：默认锚点 DHT.pondsi.com / DHT2.pondsi.com / dht.numumu.com × UDP 443/62666 自动生效，启动即引导并发布记录。第二台以第一台为锚点后自动入网、双向可发现。

消息发送后收件人没收到？

先确认收件人在线（register 后心跳）；本站投递失败会按序转给上游（扩网），8 秒预算内最多试 3 个；都不行返回 offline（不排队重试，客户端稍后换新 msgId 补发）。

DHT 对端数为 0？

确认锚点可达（UDP 443/62666 出站放行）；本机监听 UDP 端口正常（端口页）；锚点全部不可达时会退避重试并显示「引导失败」。局域网联调请互填 127.0.0.1:UDP 端口互为锚点。

附加内容没有生效？

检查：内容库已保存（非空）；该凭据的附加内容模式不是「关闭」；消息走的是中继（客户端直投）或扩网转出（F中继不加）；WArmy 客户端 25h 窗口与多份对比规则（同 msgId 多副本不一致时不展示）。
